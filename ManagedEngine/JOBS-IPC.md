# Managed jobs read

`GET /api/jobs` accepts optional `query.cursor`. Start with `{}`. The authenticated response contains base64 `chunk`, boolean `recordComplete`, and opaque `next` (or null). Append decoded bytes until `recordComplete`, decode the UTF-8 JSON record, clear the buffer and continue with `next`. Empty history returns an empty chunk, false and null. Each frame holds at most 24,000 bytes. Records preserve the source jobs projection and include the unchanged `result_json` field.

Jobs whose referenced item is missing remain in the enumeration with their original identifiers, error and result. They have `itemUnavailable: true`, null item title/media, and a retry-blocked explanation; reading does not delete, repair or execute them. Other records have `itemUnavailable: false`. A missing item does not hide the job or block traversal of older records.

`error` retains the recorded job value, including null; cause classification uses that recorded error. `stage_error` is a separate current failed-stage observation for the same item and stage, not a replacement for the historical job error or proof of that job's original cause. Aggregate jobs retain their stage details in `result_json`.

Each record is serialized once to a private temporary spool, up to 512 MiB per record; larger records return an error without truncation. The per-record snapshot remains coherent if the database changes while it is read. A fresh enumeration observes later changes. Only one snapshot exists per service process: starting another record replaces it. Continuations expire after 120 seconds, on replacement, on completion, or on process exit; restart enumeration after an invalid or expired cursor. Temporary storage is released on replacement, completion, expiry or process exit. Cursors are per-process random capabilities protected by the authenticated channel. Ordering is descending signed SQLite rowid, including its full signed range. The enumeration is not a database-wide snapshot; inserts above the cursor require refresh and deleted next records cause an error. No arbitrary paths or SQL are accepted.

The snapshot reads SQLite text cells in bounded chunks inside one read transaction and closes that transaction before returning frames. For failed aggregate (`auto`) jobs, a streaming JSON projection reads only failed stage statuses; the stored result itself is returned unchanged. Invalid or non-object aggregate JSON has no resolved stages. The 512 MiB limit counts the complete UTF-8 encoded JSON record, including escaping and object syntax; oversized records fail without truncation.

Aggregate JSON nesting is walked iteratively. The parser caches one 64 KiB nesting-state block and uses a spool with up to 64 KiB buffered in memory; deeper state spills into a private temporary file in the app-owned database directory. It reads and writes spill data at block boundaries and releases the file when parsing finishes or fails. Deep valid results remain readable and retain their stage semantics; malformed results have no resolved stages and retain their original text.
