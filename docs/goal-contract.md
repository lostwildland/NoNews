# NoNews 完整能力迁移目标

2026-10-27。状态：active。用户已批准自主推进规格、tickets、实现、测试、审查、提交和 push；不再追加需求访谈。

## 完成条件

- 现有 IO 所有活跃功能在 NoNews 有对应入口或配置；以能力矩阵逐项取证，41 项是起点而非范围上限。退出／遗留能力单列，不冒充现行功能。
- 用户全部数据库、稿件、正文、版本、身份、人工判断、来源配置、队列、采用与收录回执、外部资产映射完整迁移，并独立核对；旧 IO 数据保持可回退。
- 新用户安装 NoNews 后无需另行部署 IO／FreshRSS 后端；在原生设置内配置 AI、提示词及可选集成。
- 保留全部 NNW 基础功能；新增 IO 设置、人工决定、内容与处理结果具备实际同步路径和冲突／离线行为验证，不仅保存于一台 Mac。
- 原生 NNW 三栏、菜单、快捷键、Inspector 与 Settings 语言一致；设计和开发功能时参考 Apple 官方 [Human Interface Guidelines（HIG，人机界面指南）](https://developer.apple.com/design/human-interface-guidelines/) 并遵循适用规范，系统支持时采用原生 Liquid Glass，阅读正文以清晰度为先，支持深浅外观、Reduce Transparency/Motion、VoiceOver 和键盘。
- 用户可连续使用原有完整工作流；目标新用户可独立配置并完成筛选、阅读、加工和后续操作。UI 逐项审核，无影响任务完成的已知缺陷；不可自称获得 Apple 奖项。

## 已确认的十项决策

1. 应用管理必需本地组件；用户只配置外部服务。
2. 首版处理角色与流程沿用 IO；不新增任意阶段编排。
3. 统一 NNW 来源／列表导航，详情适配不同媒介。
4. 所有现有集成行为保留，个人联动偏好成为可配置选项。
5. Nope 清理和类似偏好保留并配置，默认与迁移用户既有设置保持连续；数据校验、安全与防覆盖不开放关闭。
6. 正文、稿件、恢复期和生命周期沿用 IO；不擅自改成永久保留或 NNW 缓存淘汰。
7. 共享内容身份，同内容不同提示词的结果共存；人的决定在同一内容共享。保留历史结果上下文。
8. 同步属于本轮必交付，不延期；调查并复用 NNW 合适接缝，不能把自定义状态塞入不支持它的 RSS 服务。
9. 完整数据库迁移和无缝衔接属于完成条件；先副本演练，不能用局部样本冒充全量完成。
10. 全能力等价＋新手可配置＋实际 UI/UX 验收；逐 ticket commit/push/review。

## 测试接缝与授权

采用用户已授权的完整用户行为验收：应用启动及 Settings、NNW article-to-IO identity bridge 的公共接口、处理服务公开命令／读取 API、SQLite backup/import/export 公共接口、同步适配器公共操作、真实原生旅程。继承已有模块测试；测试结果不能仅断言实现内部字段。具体技术接缝由 ticket 负责人调查并记载，不再要求用户批准每个测试名称。

涉及 UI 或交互的功能，从设计、实现到评审和验收都应查阅 HIG 中适用的 macOS／iOS 章节；在 ticket 设计或验收记录中注明参考链接及其对应的控件、导航、反馈、键盘和无障碍决策。以实际原生操作验证结果；仅引用 HIG 或成功编译不算界面验收。

## 执行与保护

产品、规格与 UX 由主代理负责。一个开发 ticket 由一个 GPT-6.1 Terra high 子代理实施及测试。并行开发使用 T3 隔离 worktree；同一个构建资源只运行一个大型 Xcode build，避免磁盘争用。每 ticket 起始 commit 为独立 Standards/Spec review 的固定点，主代理发起两条独立评审，修复后复核。每个完成 ticket 提交并 push，维护版本与依赖。

生产迁移使用一致性数据库备份而非复制活动 WAL 文件；核对完整性、表／记录／内容版本／文件清单及独立恢复。凭据只通过 Keychain 或私密通道处理，不进入仓库、日志、测试 fixture 或同步普通记录。旧源不删除，外部用户改动不得覆盖。
