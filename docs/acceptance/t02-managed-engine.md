## Backend dependency and source audit

The source boot graph was copied to a private temporary audit directory, excluding caches and unrelated project files. With the staged arm64 interpreter and hash-locked wheels, that temporary copy booted the real source Application, returned an empty job list, saved processors=3, and returned processors=3 after a new process opened the same synthetic database. The fixture included a source taxonomy resource and has not been sanitized for shipping. This check did not read production data or contact configured integrations; it is not a portable packaged-service test.

`requirements.lock` pins the source-declared Python dependencies and transitive wheels against PyPI SHA-256 metadata. Preparation installs binary wheels in an isolated environment with hash enforcement. An arm64 offline install from the checked wheels passed imports after relocation. Wheel distributions include their license texts in their `.dist-info` directories; observed metadata includes Apache-2.0, MIT, BSD-3-Clause, MIT-CMU, MPL-2.0 and PSF-2.0. The `mdurl` MIT notice is at `.dist-info/LICENSE`. A full fresh preparation including this installation and an Intel run remain untested.

The first standalone source module copied for the port is `io_port/settings.py` (source SHA-256 `b94fd7cda56d61893a631380af8bf105fe42b1dd3c18100267fb956516a3c1b6`); its setting read/write and invalid-value behavior have a small isolated test. It is not yet used by the adapter. Native integration and shipping remain incomplete. No missing license or user authorization is asserted as a blocker.
