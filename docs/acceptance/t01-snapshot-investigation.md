## Source evidence and coverage limits

`backend/schema.py` declares schema version 41 in `schema_meta`, and delegates DDL to many owners. Version 41 alone does not describe all historical tables: schema setup conditionally retires old body tables. Preserve unknown tables and their contents rather than assuming an exhaustive list.

`backend/content_store.py` stores body and draft versions and their text in separate tables. A version marked `imported` is a verified copy, but the corresponding literature file remains authoritative. `backend/legacy_content_migration.py` records mapping and verification evidence; it distinguishes missing, changed, unclaimed, and unverifiable files. Treating an imported copy as the file's replacement would change authority.

`backend/literature_mapping.py` defines `literature_files`, `literature_raws`, and `literature_drafts`, including relative paths, identity and file hashes. `backend/service.py` also resolves Raw through private-source records and archived artifacts, with distinct roots. `backend/media_store.py` records remote objects, upload-intent payloads and local pending staging paths. The source investigation has not established a complete, safe mapping of all these forms and roots into a portable snapshot, nor whether each historical reference represents required live data, a tombstone, or an external projection. Unmapped legacy forms and remote objects must be explicitly accounted for, not silently omitted.

The schema owners also include processing jobs, pipeline runs, settings, deliveries, media intents and receipts. A complete backup must retain their bytes and relationships, including unfamiliar tables; counting selected rows is insufficient. Database and file snapshots also need a defined consistency boundary when files change while a live SQLite backup runs.

## Developer interface and boundaries

Run `python3 scripts/io_snapshot.py snapshot DATABASE DESTINATION --root vault=VAULT` and supply `--root private_raw=PRIVATE_ROOT` and `--root paper_images=IMAGE_ROOT` when needed. Additional explicit roots can overlap: logical roles bind to subtrees of one stored physical tree. `verify SNAPSHOT` and `restore SNAPSHOT DESTINATION` are separate commands; the corresponding Python functions are public. The parent must exist, destination must not exist, and no source may overlap the destination or database. The snapshot and manifest contain private data and filenames, so keep them private. Console output does not include content, credentials or paths.

The database is read through SQLite's online backup; snapshots preserve arbitrary tables and rows without translating them. Verification checks integrity, foreign keys, schema, table counts and content hashes, version markers and asset hashes. Literature mappings are checked against `vault`, private Raw against `private_raw`, including file hash, size and owner identity. Database version text hashes and available authority mappings are checked. Format 3 stores original root names and paths and per-reference bindings; those paths are private evidence. `read_asset(restored_directory, table, column, identity)` resolves bound bytes against the restored tree and checks their hash without consulting the original roots or rewriting historical database fields. Formats 1 and 2 from earlier implementations are refused; this implementation does not upgrade them.

`recovery_binding` returns the currently checked path, SHA-256, size, device and inode; `read_recovery_asset` reopens and checks those values. `recovery_adapter` produces ephemeral staging fields for IO's document/preimage recovery without changing the stored audit row. The consumer must reopen with no-follow, require a regular single-link file, compare device/inode, size and hash immediately before use, and retain IO's existing conditional target-write checks. Binding evidence is not permission to overwrite a changed target and cannot eliminate a later race.

Bindings cover unmapped absolute Raw files, literature and private Raw mappings, literature archive sources, pending media payloads, media-document staging, activation quarantine and preimage, ingestion failure artifacts, reading/news notes, legacy cleanup-media recovery, and cleanup backups. Cleanup backup manifests and each listed body/draft are checked against their recorded hashes and counts. Source HTML gzip payloads are checked against the uncompressed hash; nested retained image archives use their own `file_hash`. Inline Markdown and quoted HTML image references are bound using the reader's `images/` role or a mapped vault document's relative root. The manifest records schema fields containing `path`, `_root` and `_json`, their handling classification, and each recognized binding; unknown populated path fields are rejected. JSON is recursively scanned for path and root keys, and unbound roots or missing files are rejected. A prepared, absent quarantine is recorded as a reservation; cleaned staging remains a tombstone, while reset-retired staging bytes remain required as specified by the source owner. `remote_references` returns object identifiers and expected hashes tagged for later live readback; no remote byte verification is claimed. The manifest's hashes are not signatures: an attacker who changes both data and manifest can forge self-consistent evidence. Independent restore tests query known synthetic values directly rather than trusting the manifest alone.

The operation inventories roots, takes an online backup, copies roots, re-inventories and takes a second backup. It refuses observed changes and bounds each backup attempt to 10 seconds. This is a conservative stability check, not an atomic transaction across SQLite and files: changes that occur and revert between observations are not detectable. SQLite read-only access to an active WAL may use SQLite's shared-memory coordination files. Quiesce writers and use independent trusted evidence before any real migration.

Publication reserves an absent destination and moves staged entries into it. A crash can leave an incomplete reserved destination; verification rejects it, and a retry never overwrites it. Remove or inspect such a directory manually only after confirming ownership. Symlinks and special files in asset trees are rejected, with no-follow file-descriptor traversal. This is not a hardened defense against an adversary concurrently replacing source database or parent directory paths.
