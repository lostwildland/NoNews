# Curator 判断与自动处理：交互建议

2026-10-25，需求讨论稿；不是已接受的实现规格。

## 用户已确认

- 第一版直接支持自定义提示词，暂缓自然语言访谈式 onboarding。
- 当前 IO 是用户认可的工作流基线，后续问题聚焦其面向更多用户的可配置化，不重复询问已查明的代码事实。
- 用户最终确认首版保留现有 IO 的数值评分、理由与阈值判断，暂不采用无分数分类替代方案。具体视觉权重留待原型比较。
- 达到条件自动运行 Editor 是需要保留的能力，不能锁定为必须逐条手动确认。
- 初加工指 Editor 生成供用户消费的 draft；不要与 Curator 筛选混同。
- 提示词复用、来源策略及历史重跑边界已确认，见 [ADR 0004](../adr/0004-reusable-prompts-and-feed-processing-policy.md)。

## 建议：解释优先，阈值仍然明确

列表主要展示一句与用户标准有关的推荐理由，可加“优先看／可浏览／暂不推荐”的简短提示；这些分档是待验证建议，不是全局质量评级。保留全部内容入口，不把低分等同于已读或人工排除。

详情可查看分数、判断依据与实际使用的材料。数值并非客观质量或可靠概率；不同提示词的分数不默认可跨方案比较。若分档由阈值映射而来，应由同一规则产生，不让标签与自动处理各用一套不一致的标准。

自动 Editor 单独显示启用状态、来源范围、当前阈值和触发理由；例如“评分 8 ≥ 设定阈值 7，已自动生成”。关闭自动生成不关闭 Curator。人工仍可对未达自动条件的条目请求生成，在材料可用的前提下执行。

未评估、材料不足、处理失败与有效低分分别显示；不能把它们都塞进“不推荐”。已有人工排除、材料有效性和版本等保护仍须遵守。

## 暂缓的替代方案与后续验证

无数值分类方案暂缓，不属于首版待实现范围。降低分数在阅读主界面的视觉权重仍为设计建议，待原型测试后决定默认呈现。

使用相同内容和同一批 Curator 输出，对比“分数优先”与“理由优先”：观察用户能否选出值得阅读的内容、解释推荐原因、发现误判，并准确预测哪些条目会自动生成。核对误筛与遗漏，而不只看点击速度。
