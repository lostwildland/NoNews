# IO script entry points and ticket coverage

2026-10-28. The [106-entry source inventory](io-script-entrypoints.json) complements the [HTTP dispatch audit](io-command-ticket-coverage.md) and [maintenance behavior follow-up](io-maintenance-port-surfaces.md). It records every non-hidden, non-bytecode file below the current reference checkout's `scripts/`, without following directory symlinks. Per-entry hashes identify the dirty working-tree bytes; Git HEAD alone does not.

The inventory contains 83 Python files, four PHP files, three shell scripts, three plist templates, seven JavaScript files, three CJS files, one dependency manifest, one license and one source alias. This includes supporting components, generated helpers, vendor resources and historical compatibility wrappers. It is **not 106 active user features**, a behavioral audit, or NoNews implementation evidence. Candidate primary/supporting ticket assignments require the owning ticket's source/caller inspection.

`scripts/sage-browser.py` is an alias of `publisher-browser.py`; its hash identifies the link text and the target has its own entry. The untracked reference helper `scripts/zotero/create-obsidian-note.loader.js` is included because tracked-file searches alone would omit it. Only source filenames, hashes and Python AST argument/main metadata were collected: no source module was imported or executed, and no installation data, credentials or configured targets were read.

Before committing this inventory, a fresh comparison found changed hashes in `archive_paper_sources.py` and `consolidate_literature.py`. The inventory was regenerated and all 106 entry names, hashes and ticket assignments were rechecked. The HTTP source hash still matches the 54-fragment audit. This is an observation boundary, not an assertion that concurrent writers cannot change the source later.

Each owning ticket must record the retained outcome and its public test/native control or configured helper seam. It must distinguish active behavior, historical-input compatibility, generated/dependency support and superseded host deployment. Unknown activation or legacy input stays explicitly unresolved; absence of a new script button does not imply lost functionality. Preserve source authority, exact targets, backups, conditional writes and evidence levels; move personal paths/preferences to configuration. Final T30 reconciles every entry's disposition against the full source manifest and current NoNews tests/UI evidence. No live service or personal migration is accepted by this list.
