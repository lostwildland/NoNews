# NNW-first 重构：十个关键决策

2026-10-27。用户要求本轮最多十个问题。用户现已回答十问；最终结果以如下答复及 ADR 0007 为准，先前建议与答复不同时采用答复。已确定的 IO 能力不再作为是否保留的问题。

1. 安装体验：首次使用是否需要单独部署 IO 后端。
2. 首版配置范围：固定 Curator／Editor，还是引入自定义阶段。
3. 媒介导航：统一 NNW 列表与按内容适配详情，还是新增媒介级导航。
4. Yep 与外部集成：如何保留现有快捷工作流并让联动可见。
5. Nope 与清理：人工排除是否同时承担延迟删除加工资产的含义。
6. 内容保留：NNW 缓存清理与已判断、已加工内容的长期留存边界。
7. 多来源多提示词：同一内容在不同来源的处理上下文如何共存。
8. 设备边界：首版新增的 AI／人工判断数据是否跨设备同步。
9. 迁移边界：个人 IO 历史数据与工作流如何进入 NNW-first 试用。
10. 验收标准：怎样证明重构改善了用户旅程，而不是只搬完功能。

收到答案后更新相应 ADR、术语与旅程文档；十问以外的实现和视觉细节由设计开发提出具体方案，不继续扩展本轮访谈。

## 用户决策结果

1. 确认应用管理必要组件。
2. 确认仍按 IO 现有处理角色和流程。
3. 确认沿用 NNW 导航。
4. 全部集成功能保留，改为用户友好的可配置、可组合方案。
5. 清理等个人偏好保留为设置；不删能力。
6. 生命周期延续 IO 当前行为，不采用新建议的统一永久保留。
7. 确认同内容多提示词上下文结果共存。
8. 推翻单机建议：同步一起实现，调查 NNW 既有同步接缝。
9. 推翻局部迁移建议：全部数据库／资产保留，完整迁移，无缝衔接。
10. 确认真实用户旅程验收；额外硬条件为 IO 全能力对应、可配置、NNW／Apple 原生 Liquid Glass、每 ticket 实施测试评审提交同步。

后续不增加本轮问题。详见 [完整能力决定](adr/0007-full-io-parity-configurable-product.md)。
