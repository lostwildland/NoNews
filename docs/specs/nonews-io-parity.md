# NoNews: complete Information OS parity in a native NNW experience

## Problem Statement

The existing owner can receive, verify, judge, process, collect, adopt and recover information in Information OS, but that workflow depends on a personal FreshRSS/Python/tooling environment. Replacing it with a nicer RSS interface that loses any active capability, historical data, automation or integration is not a successful migration. New users need the same useful abilities without inheriting personal paths, vocabularies, deployment steps or unexplained side effects.

## Solution

Extend the existing NNW application and shared data architecture with managed IO processing, native settings and article-level commands. Keep NNW navigation, accounts, read/star semantics and reader fundamentals. Bring every active IO capability into an explicit user-facing action, configurable policy, contextual detail or advanced maintenance surface. Import the complete existing IO database and required assets through a verified reversible migration. Add actual cross-device IO-state synchronization using an appropriate NNW-compatible transport and preserve ordinary RSS-account behavior.

## Implementation Decisions

- NNW remains the native application shell and owner of subscription/account/read/star behavior. New IO state is additive; no separate IO Reader or arbitrary workflow editor is introduced.
- Preserve the IO engine's observable contracts and canonical data semantics. Prefer reusing and adapting tested source logic over rewriting it merely to change implementation language. The managed processing component must be installable and launchable with the app; a dependency on an independently deployed personal service fails acceptance.
- Keep IO data separate from evictable NNW article caches. Current IO lifetime, reject-recovery and protection rules are inherited; expose preference choices without making evidence validation, path/identity checking or anti-overwrite protections optional.
- Portability requires replacing personal paths, IDs, research taxonomy, collection destinations and runtime gates with explicit app-managed configuration. Never copy secrets/private runtime values into shipping source, fixtures or public issues. Credentials use secure storage.
- Curator and Editor remain distinct roles; each reusable prompt explicitly binds a configured model/target. Feed policy selects prompts and automation. Do not add hidden model inheritance or per-feed override layers.
- Source settings, full-result batch preview, historical rerun and job snapshots must maintain consistent processing contracts. An in-flight job cannot combine portions of two configurations; the chosen snapshot boundary must be documented and tested against existing IO behavior.
- Yep/Nope are shared human decisions, distinct from Star/read/collection. The same canonical item may have multiple immutable prompt-context results. Source context chooses the relevant result and historical provenance remains queryable.
- Current IO filter and Quick view behavior is inherited, not promoted into a new custom Smart Feed editor. List state and detail rendering use the latest user-confirmed baseline, with no additional Draft list preview.
- All current integration workflows remain available with configurable targets and explicit action semantics, including existing collection intent rules, optional Yep linkage, Obsidian working copies, adoption/usage receipts, image preparation and external helper compatibility. No artificial requirement to read a Draft before acting.
- Full migration uses consistent database snapshots plus complete required file/asset manifests, exact identities and per-table evidence, rollback and independent restore. Historical import does not run models or external writes. Unsupported historical forms are retained and surfaced, never silently dropped.
- Investigate and reuse NNW CloudKit/account sync boundaries. Custom IO data needs its own supported records/channel where ordinary RSS protocols lack fields; local-only and signed-out states are explicit. Cross-device testing includes settings, decisions, results, offline convergence, conflict/deletion behavior and original read/star semantics. Claiming full sync requires more than a fake transport test.
- Native NNW/AppKit chrome and Apple's official [Human Interface Guidelines (HIG)](https://developer.apple.com/design/human-interface-guidelines/) are design authority. Consult applicable macOS/iOS sections during feature design and implementation, record the relevant guidance and decisions, and inspect native interaction/accessibility against it during review and acceptance. Liquid Glass belongs in system-supported controls/navigation; article content remains legible. Older supported OS versions use native fallback. Apple documentation and actual SDK availability govern API usage.
- Default UI English; prompt and content languages remain user-controlled. First-use setup remains direct configuration, not a new conversational onboarding system.
- All implementation/testing tickets are owned by separate GPT-6.1 Terra high delegates. Routine engineering choices, ticket granularity and established public test seams are authorized by the user's explicit autonomous execution instruction; no further requirements interview is required.

## Testing Decisions

Test observable behavior, not private helper shapes. Preserve independent expected outcomes and use existing package/XCTest and IO command/API test patterns at the highest practical public seam. The acceptance owner is responsible for preventing fixtures/mocks from being reported as live service proof.

- Native app launch/Settings/reader commands: verify clean app profile, optional AI, native menu/keyboard actions and unchanged NNW journeys.
- Managed-engine command/read boundary: deterministic source fixtures exercise all five material routes, errors, validation, automatic/manual Editor, reruns, reject timing, batch scope, receipts and recovery.
- Snapshot/import/export boundary: WAL-consistent synthetic and full real-data rehearsal, integrity checks, stable identities, counts/assets/hashes, interrupted import, repeat import, independent restore and no source mutation. Test actual backup logic instead of row-count constants.
- Identity/context bridge: same content in multiple feeds, conflicting prompt contexts, repeated observations, source changes and current/historical results without duplicate decisions.
- Sync public operations: persistent offline outbox, merge/idempotency/tombstones, two independently stored clients; real CloudKit/device validation separately recorded. Read/star service adapters remain covered by original tests.
- Integration command/readback: test idempotency, target ownership and anti-overwrite using isolated service fixtures, then configured live targets with readback for acceptance; do not auto-publish or send communications.
- UX: batched evidence from actual native windows in light/dark, narrow/wide, keyboard/VoiceOver, Reduce Motion/Transparency and critical error states; Impeccable review plus one bounded correction/confirmation pass per target.
- Per-ticket focused checks/typecheck; full relevant suite and macOS/iOS builds before final acceptance. Code review compares the pinned ticket base to its reviewed HEAD on independent Standards and Spec axes. No P0/P1 finding remains unresolved at ticket acceptance.

## Out of Scope

New recommendation learning, arbitrary user-authored workflow graphs, automatic ASR/video understanding, public publishing services not currently implemented in IO, and early localization beyond the confirmed English interface. TextFold-style fold controls are a later exploration, not a substitute for any current IO ability. Existing maintenance and advanced features are IN scope even when they are not in the everyday reader. No deployment to upstream NetNewsWire or claim of awards is included.
