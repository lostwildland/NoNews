# NoNews 用户旅程与功能重构底稿

日期：2026-10-26

校正：2026-10-27。用户已确认 NNW-first 框架，并要求全部活跃 IO 能力对应、完整数据库迁移和同步同时交付。本文接入设计受 ADR 0007 约束；自定义处理阶段和 TextFold 折叠仍为后续探索。

这份文档把 Information OS 的现有能力重新放回 NetNewsWire 的用户旅程中。目标不是把 IO 原样搬进 NNW，而是保留 NNW 的订阅、同步和阅读骨架，让 IO 能力在用户需要的时刻出现。

## 产品任务

NoNews 帮助用户在信息超过日常注意力容量时：

1. 判断什么值得投入；
2. 选择投入深度；
3. 理解选中的内容；
4. 把值得投入的内容转化为下一步产出；
5. 在足够理解后安心结束。

“处理了多少条”“清空了多少未读”“生成了多少稿”都不是成功指标。

## 重构原则

- NNW 是主产品骨架。订阅、账户、同步、文章列表、阅读状态、Star、搜索和原生阅读能力保持自然可用。
- IO 增加文章的判断、材料、加工和产出状态，不复制一套独立 Reader。
- 文章只保留一个 NNW 入口；AI 结果、正文、摘要、稿件和外部收录是同一内容的不同状态或关联资产。
- 自动处理放在后台，阅读界面只展示可理解的状态和下一步。
- Curator、Editor、Yep／Nope、已读、Star 和外部收录保持不同语义。
- 阅读呈现与处理方案分开。改变阅读层级不改变评分、采集或自动处理规则。
- 复杂配置进入设置和渐进披露区域；文章详情只显示当前判断所需的信息。

## 统一用户旅程

### 0. 接入与准备

用户先按 NNW 的方式添加账户、订阅和文件夹。AI、Zotero、Obsidian 和 Magpie 都是可选配置。

用户在设置中配置：

- Curator prompt + model；
- Editor prompt + model；
- 来源级处理开关、阈值和自动 Editor 策略；
- 可选 Integrations。

新订阅默认可以阅读，不因接入 AI 自动采集历史全文或生成稿件。

### 1. 信息进入

NNW 负责同步订阅和文章状态。IO 在后台完成：

- canonical identity 归并，避免同一内容重复判断；
- 按媒体类型选择可用材料；
- 记录材料来源、版本和可用性；
- 为符合来源设置的内容创建处理任务。

新闻、论文、Newsletter、Podcast 和 Video 不强行使用同一材料流程。材料不足、访问受阻和获取失败必须保留为明确状态，不能伪装成低分。

### 2. 列表扫描

用户仍在 NNW 的文章列表中浏览。列表卡片显示：

- 标题、来源、时间和原生阅读状态；
- Curator 分数与一条短理由；
- Yep／Nope 状态；
- Star 仍表示收藏。

默认保持时间流的可理解性，参考 NNW／FreshRSS 的时间排序。用户通过现有筛选和 Quick views 缩小范围，不另建一套 IO Smart Feed。

### 3. Curator 判断

用户打开已有 Curator 结果的文章时，首次进入的详情 Tab 叫 **Curator**，而不是 Score。按现有 IO 方式展示提示词结果，包括：

- 分数；
- 理由；
- 提示词产生的其他结果内容。

元数据的展开位置待设计。列表沿用 IO，不新增此前被用户拒绝的 Draft 状态及摘要预览方案。

分数是相对于用户标准的注意力投入建议，不是客观质量或推荐概率。不同 prompt 的分数默认不跨方案比较。

Curator 可自动运行；自动 Editor 是否启动由来源设置和阈值决定。Curator 失败不等于低分，也不自动进入 Editor。

### 4. 人的判断

用户用 Yep／Nope 表达自己的决定：

- Yep：愿意继续投入，停留当前内容；
- Nope：当前不投入，进入当前列表下一条；
- 没有下一条时显示列表已浏览完；
- 判断不修改 prompt、不训练推荐系统、不改变来源优先级；
- 判断可在现有筛选面板中查看和修改。

Yep／Nope 不等同于已读、Star 或 Zotero 收录。

### 5. 理解与渐进式阅读

详情容器继续使用分层 Tab：

- Curator；
- Draft；
- Abstract；
- Fulltext；
- Original。

在 Draft、Abstract 或 Fulltext 内，后续可加入 TextFold 式的渐进式阅读层级，让用户在概览与原文之间缩放。阅读层级属于呈现，不是新的 AI 处理阶段。

首版先保留清晰的材料／稿件 Tab，不把五级折叠当作首版硬依赖。

### 6. 初加工

Editor 生成的是供用户消费的 first-pass draft。它可以：

- 按来源规则自动生成；
- 由用户手动启动；
- 使用与 Curator 不同的 prompt 和 model；
- 多次运行并保留版本；
- 默认显示最新版本。

Draft 失败或材料不足时，原文和已有材料仍可阅读，Draft Tab 显示失败原因和可执行的下一步。

### 7. 深加工与产出

现有后续动作需要接入 NNW；不要求用户先读完 Draft 才能使用，也不新增统一的 Continue deeper 门槛。待设计的动作入口包括：

- 获取更完整材料；
- 深入阅读；
- 保存到 Zotero；
- 导出或连接 Obsidian；
- 参与期号或其他明确产出流程。

用户自定义处理阶段仍为探索方向，不计为 IO 已有能力或首版决定。入口位置及 Yep 与集成的联动仍待确认。外部写入应显示目标、内容范围、执行状态和回执。

### 8. 结束、回看与恢复

用户可以在任意阶段停止。系统保留：

- 已读和未读；
- Yep／Nope；
- Star；
- Curator 结果及证据；
- Draft 版本；
- 外部收录与回执；
- 失败、重试和待处理状态。

Activity／Needs attention 等运行状态属于后台可见性，不应成为日常阅读的主入口。

## 功能重构映射

| 现有 IO 能力族 | 在 NNW 中的用户入口 | 首版处置 |
| --- | --- | --- |
| 订阅、来源、文件夹、账户、同步 | NNW 原生侧栏与设置 | 保留并作为骨架 |
| 内容身份归并 | 文章库与后台处理 | 保留，用户默认不直接管理 |
| 新闻／论文／Newsletter／Podcast／Video 材料策略 | 详情材料状态、后台任务、来源设置 | 保留，按媒体类型显示可用性 |
| Curator 数值评分、理由、阈值 | 列表卡片、Curator Tab、来源设置 | 保留并重做呈现 |
| Editor 自动处理与手动启动 | Draft Tab、来源设置、详情操作 | 保留，避免独立 IO Reader |
| Prompt 与 Model 绑定 | Preferences → Processing、Prompt 编辑器 | 保留，统一管理 |
| Yep／Nope | 列表卡片、详情操作、滑动／快捷键 | 保留独立人工判断 |
| 已读、Star、搜索 | NNW 原生控件 | 保留原生语义 |
| 组合筛选、Quick views | NNW 同一筛选面板 | 沿用 IO，暂不新增自定义 Smart Feed |
| Tab 阅读层 | NNW 原生详情容器 | 保留 Curator、Draft、材料 Tab |
| 版本、证据、身份、材料来源 | 详情中的 provenance 与版本入口 | 保留，渐进披露 |
| Activity、Jobs、失败分组、重试 | Activity／Needs attention | 保留为后台恢复入口 |
| Zotero、Obsidian、期号采用 | Integrations 与深加工动作 | 保留为可选连接 |
| 数据库正文、稿件版本和恢复窗口 | 后台存储与详情历史 | 保留，通过设置和历史入口管理 |
| 历史迁移、旧文件归并、部署脚本 | 单独迁移／维护工具 | 不进入日常阅读主流程 |
| 个人 feed ID、期刊范围、vault 规则 | 用户配置或迁移适配 | 不当作产品不变量 |
| 自动 ASR、通用批注、通用 CMS | 暂无统一用户入口 | 不纳入首版承诺 |

## 核心旅程与完整验收

```text
NNW 订阅与同步
  → 文章列表
  → Curator 分数与理由
  → Yep / Nope
  → Draft（自动或手动）
  → 原文与材料 Tab
  → 明确的深加工／集成入口
  → 可安全结束、回看和恢复
```

上述核心旅程不是缩减范围：全部活跃 IO 能力（包含已有期号采用、回执、恢复、历史工具和高级配置）必须在 NoNews 有对应；完整数据库／资产迁移与同步同属最终验收。任意处理路径、TextFold 五级折叠、推荐学习和 IO 未实现的新型发布服务不属于本轮新增。详见 goal-contract 与能力验收矩阵。
